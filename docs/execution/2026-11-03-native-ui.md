# Android app: native UI over the web app's own logic

- **Date:** 2026-11-03 (decided 2026-11-02 21:48 UTC−3, 2026-11-03T00:48Z)
- **Status:** accepted
- **Instructions:** [`docs/instructions/design.md`](../instructions/design.md) (Stack); request in chat

## Context

Opening the web app from Firefox's home-screen shortcut is slow, partly Firefox's own start
([fast-start](2026-11-02-fast-start.md)). The user wants an Android-native app, updated by re-porting the web app
about weekly: new things are tried in the browser first.

Options weighed in chat:

- **WebView shell** (the web UI in an app): no lag, but not native UI.
- **Full native port** (the old one: [android-port](2026-10-15-android-port.md), removed in
  [android-removed](2026-10-26-android-removed.md)): two copies of calculations, sync, encryption and file formats
  sharing one backup; a slight difference corrupts it, and the web app changes fast (85 commits, +5.3k lines in a
  7k-line app since that port began).
- **Native UI over the web app's JavaScript**: the calculations, data and sync stay one copy, run inside the app.

## Decision

**The native UI** (user, 2026-11-02 21:48 UTC−3: "do the native UI"). How it's built is logged as it's built, in this
file's successors.
