# Foods: one list, units per food

- **Date:** 2026-10-15
- **Status:** accepted
- **Instructions:** [`docs/instructions/design.md`](../instructions/design.md) (Homescreen, Logs, Foods screen)

## Context

After [unified items](2026-10-15-unified-items.md), the user asked for one word to cover ingredients, recipes and
concoctions, and for one button. Unit conversions should live in the same place, since a conversion always belongs
to a food. User decisions in chat: **"Use Foods"**, units per food as proposed, **drop "any item" conversions**,
and **"Update design yourself, keeping the format"**.

## Decisions

- **Word: Foods.** Home button "Foods" → `#/foods`, a single searchable list (search box on top, same matching as the
  picker), with "+ add new food" as the last element. Recipes and concoctions carry a small kind tag. The editor is
  titled "New food" / "Edit food". Pickers say "Search foods…".
- The Database menu and the separate Ingredients/Recipes/Concoctions/Conversions screens are removed.
- **Units per food:** `item.units = [{fromAmount, fromUnit, toAmount, toUnit}]` (e.g. 1 slice = 30 g), edited in a
  "Units" section of the food editor with free-text units. `unitFactor()` takes the food's own units and
  still chains through built-ins (1 loaf = 500 g → kg, oz…).
- **Log unit dropdown** (`unitsFor()`): the food's own unit first, then built-ins, `portion` and the food's defined
  units, keeping only those that convert. It no longer considers units from other foods.
- **"Any item" conversions dropped.** Only built-in mass/volume conversions apply to every food.
- Data in the code is still called `items` (table, `itemId`) to avoid another migration. "Food" is the UI word.

## Migration

- Dexie v5 attaches each food-specific conversion to its food (`moveConversions()`, matching by `itemId`, or
  `itemKey` as fallback). Generic conversions are dropped. v6 deletes the `conversions` table.
- Exports are `version: 3` (tables: items, logs, config). Importing v1/v2 files runs the same steps.
- Verified in headless Chromium: a v4 DB with one food conversion (1 slice = 30 g) and one generic conversion became
  Bread with unit `slice` (generic one gone). "Toast" = 2 slices still computes (P 5.4). Added `1 loaf = 500 g`. The log
  dropdown for Bread offered `g, kg, lb, loaf, mg, oz, slice`, and 0.5 loaf → P 22.5. No console errors.
