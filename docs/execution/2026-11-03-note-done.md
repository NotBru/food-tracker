# Temp notes: a "done" mark; no keyboard on a phone

- **Date:** 2026-11-03
- **Status:** accepted
- **Instructions:** [`docs/instructions/design.md`](../instructions/design.md) (Temp notes screen); user's TODOs:
  "Have templogs have a field for whether they've been taken care of, so that agents can trivially tell whether they
  need to think about it", "Templogs opening the keyboard by default (cellphone) are a hassle"
- **Amends:** [Temp notes](2026-11-02-temp-notes.md) (its open question: what the skill does with notes it logged)

## Context

The log-food skill told logged notes apart by checking whether their meals were already in `day`: work on every run,
and a guess for notes with nothing to log (dev notes, reminders). A new note focused its text box, so on a phone the
keyboard covered the Camera and Gallery buttons, which most notes start with.

## Decision

- Notes get `done: true` once taken care of (absent otherwise, so older rows and older apps need nothing). No format
  bump: an optional field.
- **App**: the note editor has a "Done" switch; the list shows "✓ done" beside the time and dims the note's text and
  pictures. Done notes still expire after a week like the rest.
- **Skill**: `notes` lists the notes not done in full (text, pictures downloaded) and the done ones after them, one
  line each (time, first line, picture count); `notes --all` lists everything in full. A batch's
  `notes: [{ "id": "note:…", "done": true }]` marks them (`false` unmarks); SKILL.md has the skill mark the notes it
  logged, and those with nothing to log, in the same batch.
- **Keyboard**: the text box of a new note is focused only on a computer (`useComputer`, a fine pointer), as the
  dropdowns already tell them apart.

## Alternatives considered

- **Deleting notes once logged**: they'd be gone for the user too, who may want to look back within the week.
- **`doneAt` (a time) instead of a flag**: nothing reads when.
- **Never focusing the text box**: on a computer typing first is the common case.

## Verification

- Headless Chromium: a new note on a computer focuses the text box; on a phone (Pixel 7 emulation) nothing is
  focused. Marking a note done and saving shows "✓ done" in the list, and the switch is on when it's reopened.
- `food.mjs notes` against the real backup lists the notes (none done yet); `push --dry-run` of a batch marking one
  done prints `note:… done`; an unknown id and a non-boolean `done` are refused. Nothing pushed.
- `npm run build`.
