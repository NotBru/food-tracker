# md2html.sh: compile markdown notes to self-contained HTML

- **Date:** 2026-10-21
- **Status:** accepted
- **Instructions:** none — user request in chat: "a `.sh` that I can run in this container to compile any
  `.md`" (GitHub-flavoured, for notes such as `docs/notes/error-handling.md`, which use `$…$` math)

## Context

The container has no pandoc, LaTeX or headless browser. A first version that rendered in the browser
from CDN scripts was slow to appear and unreadable when its stylesheet didn't load.

## Decision

`./md2html.sh in.md [...]` (or `in.md -o out.html`) writes `in.html` beside each input. On first run it
`npm install`s pinned markdown-it, markdown-it-texmath, KaTeX and github-markdown-css into
`~/.cache/md2html` (outside the repo), then renders server-side: GitHub CSS and KaTeX CSS inlined,
KaTeX's woff2 fonts embedded as data URIs (~430 KB per page). The output needs no network, follows the
system light/dark theme, and prints dark-on-white — "Save as PDF" from the browser is the PDF route.

## Alternatives considered

- **pandoc** — not installed; its default styling isn't GitHub's.
- **Client-side rendering from CDNs** — the first version; blank until scripts load, fragile offline.
- **Real PDF output** — needs LaTeX or a headless browser, neither of which is in the container.

## Consequences

- First run needs npm registry access; afterwards it works offline.
- Changing a version in `DEPS` reinstalls automatically.
