# Production image of the web app

- **Date:** 2026-10-26
- **Status:** accepted
- **Instructions:** [`docs/instructions/design.md`](../instructions/design.md) (Stack)

## Context

The app goes to a VPS at https://track-shit.notbru.xyz, run by another Claude instance (the "VPS agent") that the
user relays messages to. Its handover asked for an image that builds `app/` and serves `dist/` over plain HTTP on
port 80, relays `/off-search/*` like `vite.config.js`, and caches `/assets/*` for good and everything else
`no-cache`, plus a Deploy section in the README.

## Decision

- `deploy/web/Dockerfile` (context: repo root) and `deploy/web/Caddyfile`: the VPS agent's draft, moved under
  `deploy/web/` so the backup server's image can sit beside it. Node 22 builds (as `serve.sh`), `caddy:2` serves.
- Added to the draft: `encode zstd gzip` (fdc.json 3.1 MB → 0.78 MB, ciqual.json 1.4 MB → 0.40 MB on the wire) and
  `admin off` (nothing reconfigures Caddy in the container). Formatted with `caddy fmt`.
- `.dockerignore`: `.git`, `.claude`, `.devcontainer`, `docs`, `app/node_modules`, `app/dist`, `app/serve.log`.
- README: a Deploy section (the VPS agent reads it from the repo); `master` is deployed.
- The service worker is unchanged: it's network-first, so with `no-cache` a new deploy shows on the next load.
  Precaching and update prompts are the next step.

## Alternatives considered

- **Dockerfile at the repo root**, as drafted: fine for one image, crowded once the backup server has one.
- **nginx**: Caddy was already drafted, and the VPS runs Caddy, so one config language.

## How it was checked

Docker installs in the devcontainer but can't run containers (no `CAP_SYS_ADMIN`: mount and unshare are denied,
with overlayfs and vfs alike), so the image steps were replayed without it:

- A copy of `app/` as the build context leaves it; `npm ci` and `npm run build` on Node 22.23.3.
- Caddy v2.11.7 with the Caddyfile (`caddy validate`, then run with only the port and root changed):
  - `index.html`, `/`, `sw.js`, manifest, icon, JSON tables: `no-cache`; `/assets/*.js`: `immutable`; text is
    zstd/gzip-encoded; a matching `If-None-Match` gets 304; an unknown path gets 404.
  - `/off-search/search?q=…` returns Open Food Facts' JSON hits.
- Headless Chromium (Playwright 1.55.0): the app renders with no console errors, the service worker registers, the
  page fetches `/off-search` and both tables, an offline reload still renders the app, and a changed `index.html`
  shows on one reload.

Not checked: `docker build` itself. Its first real run is on the VPS.
