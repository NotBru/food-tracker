# Food screen: Edit and Info tabs

- **Date:** 2026-10-16
- **Status:** accepted
- **Instructions:** [`docs/instructions/design.md`](../instructions/design.md) (Foods screen: "Every value should also have a corresponding error")

## Context

User: "I want that place to have two tabs actually: edit, and info. The info one should show the amounts with
their errors."

## Decision

- An existing food's screen has a segmented **Edit | Info** switch. The tab lives in the URL (`?tab=info`) and
  switches with `replace`.
  - The Foods list opens Edit, as before. The breakdown screen opens Info.
  - A new food has only the form.
- The form **stays mounted** (hidden) while Info is shown, so unsaved edits survive a look at Info. Info shows
  the *saved* food.
- **Info, Amounts:**
  - the amount the nutrients are given per;
  - each unit conversion, as typed and as "1 <unit> = x ± Δ <unit>" with its worst-case range and relative error;
  - for recipes, each component's amount ± Δ and its energy contribution.
- **Info, Nutrients:** a "per <amount> <unit>" picker (any unit the food converts to) and a table with each
  nutrient's value ± Δ, range and relative error.
  - The table is computed with `nutrientsFor`, the same code consumptions use, so it shows exactly what a
    consumption of that amount would count.
- The screen title is now the food's name, no longer "Edit food".

## Verification

Headless Chromium, Egg: 140 ±5 kcal per 100 ±1 g, with 1 u = 50 ±5 g.
- Info shows "100 ±1 g · 99–101 (±1%)" and "1 u = 50 ±5 g · 45–55 (±10%)".
- Per 100 g: 140 ±6.5 kcal. Per 1 u: 70 ±10.6 kcal, which matches the hand calculation 145·55/99 = 80.6.
- An unsaved name edit survived Edit → Info → Edit.
- No console errors.
