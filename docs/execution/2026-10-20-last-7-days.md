# Dashboard: a "last 7 days" window

- **Date:** 2026-10-20
- **Status:** accepted
- **Instructions:** [`docs/instructions/design.md`](../instructions/design.md) (Homescreen dashboard); request in chat

## Context

User: "Also add a 'last 7 days' (today included) tab as well. The correction is using the last 6 days, no? instead
of just the week". Yes: since [correction-per-bound](2026-10-18-correction-per-bound.md), the daily calorie
correction looks at the 6 days before the day shown, across week boundaries. So the Weekly window (Monday →
Sunday) could disagree with it. That entry noted the mismatch as a consequence.

## Decision

- A new window, `last7`, shown as **Last 7 days**, between Daily and Weekly: daily → last 7 days → weekly →
  monthly. The arrows, the swipe and the dots cycle through it like the others; `?win=last7` in the URL.
- Days: the 6 days before today, plus today (`windowDays('last7', day)`). That is the same set of days as the
  correction behind today's range.
- Figures as in Weekly/Monthly: per-day averages over the days with consumptions, with the targets averaged over
  those same days. Today counts as soon as it has a consumption, partial or not.
- It always ends today. The day arrows stay Daily-only, as before.

## Alternatives considered

- **Make Weekly rolling.** That would change a window people already read as the calendar week. Not asked for.
- **Follow the day picked in Daily** (the 7 days ending there). The arrows don't show outside Daily, so the
  window would end on a day the screen can't show or change. Not asked for.

## Consequences

- Web app only (the Android port has neither the correction nor this window).
- While today is partly logged, it pulls the average down. Same as Weekly with the current week.
