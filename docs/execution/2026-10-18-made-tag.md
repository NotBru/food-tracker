# Concoctions: made-at time as a tag, not part of the label

- **Date:** 2026-10-18
- **Status:** accepted
- **Instructions:** [`docs/instructions/design.md`](../instructions/design.md) (Foods screen → Made at); request in chat

## Context

A concoction was shown as "Lentil soup · Home — made 2026-10-18 12:41". The user didn't like the made-at
time sitting in the name behind a long dash. They want to be able to pick out, say, every flat white they've
made, in some future query. They asked for it to be a flag instead.

The data already kept them apart. `name` holds only the name, and the time is in its own `madeAt` field
(being a concoction follows from having it, `kindOf`). Only the shown label (`itemLabel`) joined them.

## Decision

- `itemLabel` is now name, brand and attributes only.
- The made-at time is a separate tag, `MadeTag` ("made 2026-10-18 12:41", a muted pill). It shows wherever a
  food's label is listed: consumptions, Foods, picker suggestions, the breakdown, and a recipe's components on
  the Info tab. A picked concoction's tag sits under the picker box, since the box can only hold text. This
  keeps two batches of the same soup apart.
- The tag replaces the "· concoction" kind marker; "· recipe" stays.
- Searches still match the made-at date (`searchText`), so typing "2026-10" finds that month's batches.
- No data change. A query for every flat white is `name == "flat white"` (or with `madeAt` set, for only
  the ones made).

## Alternatives considered

- **Keep the date in the label, styled differently.** The label is also the picker box's text, so the date
  would still be read as part of the name there.

## Consequences

- Web app only. The Android port still shows the made-at time in the label.
